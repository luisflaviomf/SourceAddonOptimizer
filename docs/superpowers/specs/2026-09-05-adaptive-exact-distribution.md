# Adaptive exact distribution integration

User approved integrating the experimentally validated compression methods into the real WPF GmodAddonOptimizer, not the legacy Python GUI.

The first integrated release adds a separate exact distribution stage usable on a native addon or on the output of the existing quality optimization stage. It must never silently run car-specific geometry rules on weapons/props, nor claim that lossy quality optimization is byte-exact. Existing native quality controls remain unchanged. Additional native structural research adapters are not silently promoted: each needs its own generic integration/equivalence proof.

The exact stage selects frozen VVD P1 / portable VVD by structural compatibility, frozen VTF P2 versus known-size LZMA for compatible asset paths, and native fallback. MDL, DX90 VTX, VTF and WAV can use the already proven source-asset-lzma-known-size-exact/v1 domain. The new code packages these methods without research-machine paths. Every selected blob must independently decode equal to input bytes and SHA-256. Runtime/contract/support overhead is included in the final net-gain gate. DX80 and SW are excluded only from new output, with an explicit report; DX90 and originals are preserved.

Frozen source copies are preserved byte-for-byte with provenance hashes. Wrappers may adapt addon naming, runtime registry keys and physical support paths, not frozen algorithms. Distinct candidates must not share autorun paths, contract paths, support aliases or runtime terminal state. A candidate has a stable required folder name. Runtime corrupt fails closed, cold reconstructs and authenticates, warm authenticates cache and reuses it without decoding. Inputs already containing this or an experimental distribution runtime are rejected rather than blindly nested.

Output is a new independent tree, never an in-place mutation, never an automatic addon installation, never a baseline promotion. Pre/post inventories and hashes bind inputs and outputs. Source/output/work overlap, reparses and existing output are rejected before writes. Cancellation/failure does not yield a successful candidate report. The report distinguishes offline exactness from actual engine/visual validation.

WPF uses packaged worker through a runner with argument lists, progress, logs, cancellation and an output/report link. Tools stay under LOCALAPPDATA. CLI must work without the workshop research checkout. Release must package current code/templates, not a stale worker. Cars/weapons/props and engine corrupt/cold/warm verification are gates before declaring a universal default; missing verification remains visible, never inferred from previous corpus receipts.

In addition to standalone export, the existing Pipeline may opt into the exact stage after successful Models and Compress. This opt-in defaults off while experimental, must use the native stage output as read-only input and a fresh sibling destination, and must expose its own result rather than calling lossy optimization byte-exact. Cancellation/failure must prevent an overall success claim, and the native intermediate remains available. This supplies a combined workflow without changing native quality defaults.

All approved/frozen baselines, pointer, codecs, manifests, original addons and rollbacks stay read-only.
